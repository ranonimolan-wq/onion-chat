# Bug Fixes — 2026-06-28 v2 (SOCKS5 Integration)

Bu oturum, ShadowShare'a SOCKS5 proxy üzerinden anonim bağlantı desteği
ekledi. `--anon` bayrağı artık "not implemented" uyarısı vermek yerine
Tor'un varsayılan `127.0.0.1:9050` SOCKS5 endpoint'ine bağlanıyor.

## Önemli Değişiklikler

### 1. Yeni modül: `src/socks5.rs`
- **Sorun**: `--anon` bayrağı sadece `warn!` logu veriyordu; gerçek bir
  anonimlik katmanı yoktu.
- **Çözüm**: RFC 1928 istemci tarafı implementasyonu yeni bir modül olarak
  eklendi. Tek sorumluluk: `TcpStream`'i SOCKS5 proxy üzerinden hedefe
  tünellemek. Detaylar için [[socks5]].
- **Dosya**: `src/socks5.rs` (yeni)

### 2. `network::Connection::connect_via_socks5` metodu
- **Sorun**: Mevcut `Connection::connect` sadece direkt TCP'yi destekliyordu.
- **Çözüm**: Yeni `connect_via_socks5(target, socks5_addr, file)` metodu
  eklendi. Önce SOCKS5 proxy'ye TCP bağlanır, `socks5::connect` ile hedefe
  tünel açar, sonra normal ECDHE el sıkışmasını çalıştırır. Mevcut `connect`
  metodu değiştirilmedi (Rule 7 ihlal edilmedi).
- **Dosya**: `src/network.rs`

### 3. `main.rs` CLI: `--socks5` bayrağı + `--anon` semantiği
- **Sorun**: `--anon` hiçbir şey yapmıyordu; kullanıcı SOCKS5 adresi
  veremiyordu.
- **Çözüm**: `Connect` alt komutuna `--socks5 <addr>` eklendi. `resolve_socks5`
  yardımcı fonksiyonu:
  - `--socks5 <addr>` verilmişse o adres kullanılır.
  - Sadece `--anon` verilmişse Tor varsayılanı `127.0.0.1:9050` kullanılır.
  - İkisi de verilmemişse `None` (direkt TCP).
- **Dosya**: `src/main.rs`

### 4. `Listen` alt komutu için `--anon` uyarısı güncellendi
- **Sorun**: Eski uyarı "Anonymity mode is not yet implemented" yanıltıcıydı —
  istemci tarafında artık implement edildi.
- **Çözüm**: Yeni uyarı: "Anonymity mode for listener is not yet implemented
  (requires Tor hidden service)." Sunucu tarafında SOCKS5 mantıklı değil;
  ileride hidden service entegrasyonu için ayrı çalışma gerek.
- **Dosya**: `src/main.rs`

### 5. Clippy `doc_lazy_continuation` uyarıları
- **Sorun**: `socks5.rs`'taki modül dokümantasyonundaki liste öğelerinde
  devam satırları yeterince girintisizdi (clippy strict mode yakaladı).
- **Çözüm**: Liste öğelerinin devam satırları 3 boşluk girintilendi.
- **Dosya**: `src/socks5.rs`

### 6. Testlerde `socks5::connect` → `crate::socks5::connect`
- **Sorun**: `socks5.rs` test modülünde `use super::*;` var ama `socks5::connect`
  çağrısı modül yolunu çözemedi (`E0433`). `super::*` sadece item'ları
  import eder, modülün kendisini ismiyle erişilebilir kılmaz.
- **Çözüm**: Tüm test çağrıları `crate::socks5::connect` olarak değiştirildi.
- **Dosya**: `src/socks5.rs`

### 7. Çince karakter "上层" → "üst seviye"
- **Sorun**: `socks5.rs` modül başlığında tesadüfen Çince karakter kalmış.
- **Çözüm**: "üst seviye bağlantı yönetimi" ile değiştirildi. Rule 2
  (Türkçe/İngilizce bilingual) ihlal edilmedi.
- **Dosya**: `src/socks5.rs`

## Yeni Özellikler

- **`socks5::connect(stream, target)`** — SOCKS5 el sıkışması. Public API.
- **`Connection::connect_via_socks5(target, socks5_addr, file)`** — SOCKS5
  üzerinden ECDHE bağlantısı. Public API.
- **`DEFAULT_TOR_SOCKS5`** — `"127.0.0.1:9050"` sabiti. `main.rs`'ta.
- **`resolve_socks5(anon, socks5)`** — CLI bayraklarını çözen yardımcı.
- **5 yeni SOCKS5 testi** — sabit değerler, hata kodları, 3 uçtan uca
  el sıkışma senaryosu (başarılı, auth-reddi, REP hatası).

## E2E Doğrulama

Üç gerçek proses testi çalıştırıldı:

### Test 1: Direkt TCP (port 8080)
```bash
# Terminal 1:
shadowshare listen --listen 127.0.0.1:8080
# Terminal 2:
shadowshare connect --connect 127.0.0.1:8080 --file /tmp/e2e/test-input.txt
```
**Sonuç**: ✓ Dosya alındı, md5 birebir aynı (`d7dffb84...`).

### Test 2: Binary dosya, direkt TCP (port 8081)
```bash
shadowshare connect --connect 127.0.0.1:8081 --file /tmp/e2e/random.bin
```
**Sonuç**: ✓ 98 KB binary dosya alındı, md5 birebir aynı (`586aeb96...`).
Bu aynı zamanda v2 chunked transfer'in çok-parçalı senaryosunu doğrular.

### Test 3: SOCKS5 üzerinden (port 8082, proxy 11080)
```bash
# Terminal 1: shadowshare listen (8082)
# Terminal 2: Python sahte SOCKS5 proxy (11080)
# Terminal 3:
shadowshare connect --connect 127.0.0.1:8082 --file /tmp/e2e/test-input.txt \
                    --socks5 127.0.0.1:11080
```
**Sonuç**: ✓ Proxy log `CONNECT ('127.0.0.1', 8082)` gösterdi; dosya
alındı; md5 birebir aynı. Bu, `socks5.rs` + `network.rs` + `file_transfer.rs`
zincirinin gerçek bir SOCKS5 proxy'si üzerinden uçtan uca çalıştığını kanıtlar.

Sahte SOCKS5 proxy'si `/home/z/my-project/scripts/fake_socks5_proxy.py`
olarak saklandı (Python 3, async, RFC 1928 minimal).
